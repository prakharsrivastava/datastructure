Multi-Dimensional Hashing & Grid File Structure
ashing is typically used for single-dimensional keys (e.g., mapping user IDs to hash buckets). However, when data has multiple dimensions (e.g., spatial coordinates in 2D/3D), standard hashing techniques do not work efficiently. Multi-dimensional hashing solves this problem.


Concatenation-based Hashing
Combine multiple dimensions into a single key.
Example: If we have a (x, y) coordinate, we could hash "x_y".
Issue: This approach does not preserve spatial locality (i.e., close points might hash to completely different values).


Grid-Based Hashing (Grid File Structure)
Treats each dimension separately and organizes data in a multi-dimensional grid.
This is more efficient for spatial searching and nearest neighbor queries.


Concatenation Hashing	Merges dimensions into one key	Simple but loses spatial locality
Grid File Hashing	Divides space into grid cells	Efficient for multi-dimensional range queries
Space-Filling Curves	Maps multi-dimensional data to 1D order	Optimized for disk storage

grid files 
Assume the X and Y coordinates range from 0 to 100.
We will divide the space into a 4x4 grid.

Grid files require multi-dimensional indexing, which can be expensive for high dimensions.
Hard disks are inherently one-dimensional (data is stored sequentially).
Space-filling curves flatten multi-dimensional space into a 1D sequence, preserving locality better than standard hashing.
